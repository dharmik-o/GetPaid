## Found and fixed

- `tests/list-pages.test.ts` matched `<Link className="button" href="...">` exactly, so a `data-tour` attribute broke it. The pattern now allows extra attributes; it still checks the same links and labels.
- `tests/theme-contrast.test.ts` (box-shadow must be a hard edge): the first cut-out shadow used `rgba(...)` with commas and `100vmax`, which the test's parser can't read. The ring now uses `0 0 0 9999px rgb(20 18 10 / 0.6)`, which it accepts.
- Every other e2e spec would have been covered by a tour card, so global setup marks the demo user's tour as skipped and all tips as seen. `zzz-tour.spec.ts` starts it by hand and puts it back.

## Not caused by T1, but the owner should know

- `tests/invoice-pdf.test.ts` and `tests/invoice-signature.test.ts` (headless Chromium) time out at 60 s when the whole suite runs at full parallelism on this PC. They pass alone (2.6 s), pass with `npx vitest run --maxWorkers=3`, and the same two time out on untouched `main` (checked in a throwaway worktree). They passed in the first full run of the session, so it depends on the machine's load. `npm run check` fails on this PC for that reason until the workers are limited.
- The first full e2e run (with a full `npm run check` running beside it and Docker just started) had 32 failures that came from load; the same suite run alone was 140 passed.
