# QA: A4 calendar import

Solo mode, 9 Nov 2026. Branch `feat/A4-calendar-import`. Security-heavy step, so the review below is longer than for the others.

## Checked

- `npm run check`: green (103 files, 2534 tests passed, 1 skipped, after the upload fix).
- `npm run test:e2e`: 136 passed (run before the upload fix below, which no browser test touches; the upload route is covered by the unit tests).
- Diff reviewed against `docs/PHASE2-PLAN.md` sections 2, 7.A4 and 11.
- **A-S3** (`tests/phase2/safe-fetch.test.ts`, 29 tests): `http://`, `127.0.0.1`, `localhost`, `*.localhost`, `169.254.169.254`, `10.x`, `172.31.x`, `192.168.x`, `100.64.x`, `[::1]`, `[fd00:ec2::254]`, `[::ffff:10.0.0.5]`, `2130706433` (an IPv4 address written as one number), a name with no dot, a user name and password, and another port are all `blocked_address`, and the transport is never called. A host resolving to a private address, and one with a private address among several answers, are refused. A redirect from a public host to `10.0.0.5`, to a host whose DNS answer is private, and to plain `http` is refused and the target is never requested. A loop gives up after 3 redirects (4 requests). The connection is made to the address that passed the check, with one DNS lookup. A body over 5 MB is `too_large`, an HTML page is `not_ics`, a 404 is `http_error`, a silent server is `timeout` after the limit, and failing DNS is `unreachable`. I checked the tests can fail: with the address check switched off, 15 of them failed (restored).
- **A-S4 and A-S5 and A-C1** (`tests/phase2/calendar-import.test.ts`, 16 tests): no response of the add, list, update, refresh or upload routes contains the secret path, the file name or `url_enc`; the stored value is ciphertext that decrypts with the owner's context and not with another user's; nothing written to the log (stderr) contains the secret or even the host, on success, on a failed refresh and on a refused address (I checked this one can fail by adding a log line with the address: it went red; removed). Weekly event with an EXDATE and a moved occurrence expands to the four right instants; cancelled events and cancelled occurrences are skipped; an all-day event keeps its dates; a zone comes from its VTIMEZONE; control characters are removed from titles; non-iCalendar text throws; an attendee email matches a client (case-insensitive) and no email is stored. Adding a source served by msw syncs its events; a 404 sets `last_error = http_error` and keeps the old events; refreshing twice inside a minute answers 429; the scheduled run syncs a due source once, as its own user; a file upload works once and a non-calendar is refused; a switched-off source's events are hidden and a removed source's events go.
- **Browser** (a throwaway Playwright spec on the E2E server, not committed): the Imported calendars page loads; an `http://` address gives "Address must start with https:// (or webcal://)" without repeating the address; `https://127.0.0.1/...` is added, shows "This address isn't allowed" and only the host; uploading an `.ics` file with a weekly event shows "3 events, imported ..."; the calendar's month view shows the three Standup occurrences, marked as a client meeting because the attendee is the demo client; the sources API response has no `url_enc`.

## Rules checked (plan section 2)

- **Rule 1 (untrusted text):** imported titles, locations and attendee emails are data. They are stored as text (control characters removed, cut to 200), never executed, and nothing imported touches money, invoices, reminders or settings. They reach the AI only in A5.
- **Rule 6 (secrets):** the address is encrypted with `lib/crypto.ts` bound to `calendar-source:<user id>`, selected only inside `syncSource`, never returned (the list query doesn't select it), never logged. Errors and field messages don't repeat it.
- **Rule 7 (outbound fetches):** `safeFetchText` is the only code that fetches a calendar address (searched: the only caller is `calendar-import.ts`). It resolves the host itself, refuses any private or special answer, connects to the checked address, re-checks every redirect, follows at most 3, and has 10 s and 5 MB limits.
- **Rule 8 (service role):** only `runCalendarSync`'s claim query uses it, and each sync then runs as the source's user. The routes the browser calls use `runAsCurrentUser`.
- **Rule 9 (logging):** only event names, ids, counts and reason codes.
- **Don'ts (section 11):** no meeting notes, no write-back to outside calendars, no calendar URL fetched except through `safeFetchText`, nothing returned unencrypted, nothing logged.

## Found and fixed during QA

- Linting found a literal byte-order-mark character where I meant the escape `﻿` (the tool I wrote the file with kept the real character); fixed in code and test. Typecheck found `msw`'s option is `onUnhandledFrame` in this version; fixed in the tests.
- `prettier --write` on a whole folder reformatted seven unrelated files. I reverted them, so the diff holds only my changes. Worth knowing for next time: format named files only.
- **Found in review, fixed:** the upload route read the whole body with `request.text()` before checking its size, so a chunked upload with no `Content-Length` could use unbounded memory before being refused. It now reads the stream and stops past 2 MB with a failing test first (`the upload size limit`: 21 chunks were read before the 413, now fewer than 8).

## Accepted risks and limits

- Parsing a 5 MB file is synchronous and can take a second or two of CPU. A file is only parsed after the size check, expansion is capped (20,000 steps per event, 5,000 occurrences per source), and only the signed-in owner can trigger it, so I left it.
- A time with no zone is read as UTC, and an occurrence moved into the window from after it is missed (both written in the code comment and in `docs/DECISIONS.md`).
- Source colours are stored but not yet drawn in the month view.
