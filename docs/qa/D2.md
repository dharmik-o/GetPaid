## Found and fixed during QA

- **Client data in the image.** `.dockerignore` had `.data`, which matches only the repo root; `apps/web/.data` (dev invoice PDFs, about 8 MB) was copied into the image. Changed to `**/.data` and `**/invoice-archive`, rebuilt, and confirmed the folder is gone. The leaky image was deleted. It never left this PC.
- **PDFs would have failed in production.** The standalone build didn't include `playwright-core/browsers.json`. The Dockerfile now copies the whole package.
- Fonts were already handled in the first version (copied from `node_modules/@fontsource`), confirmed present in the container.

## Rules checked (plan section 7)

- No Docker socket mounted anywhere. The app doesn't start or stop containers.
- Only Caddy listens publicly (80 and 443).
- Only `/webhook/*` goes to n8n.
- No secrets in the image, the Caddyfile or git: the context excludes env files, and `docker-compose.prod.yml` reads `.env` only at run time. `DOMAIN`, `DEMO_*` are documented in `.env.example` with empty or safe defaults.
- "Don't let production run without the demo gate" is D3's job. Until D3, `currentUserId()` still throws in production, so the stack serves `/welcome` and the webhooks only.
