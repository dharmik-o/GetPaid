# QA: A6 Calendar clicks

Solo mode, 10 Nov 2026. Branch `feat/A6-calendar-clicks`. Built from the owner's feedback on the calendar page.

## Checked

- `npm run check`: green (111 files, 2682 tests passed, 1 skipped).
- `npm run test:e2e`: 137 passed (136 before, plus the new `tests/e2e/zz-calendar-clicks.spec.ts`). The dev server's log showed one long dump of a database connection object during the run; every test passed and I did not look into what logged it.
- New tests (`tests/phase2/calendar-clicks.test.ts`, real migrations and RLS in PGlite):
  - `GET /api/calendar` answers 400 with "and to must be dates like 2026-12-31..." for no dates, a month that isn't real, a word instead of a date, `to` before `from` and a range over 400 days.
  - The month the grid asks for returns only the signed-in user's items; nothing of the other user (keys, names) appears.
  - Every item has a summary; a message body stored in the database never appears in any item; the invoice summary shows `USD 900.00` from 90000 minor units; the milestone summary is "Milestone 1 of Website redesign for Client a · 30% of the project · due".
  - An imported event titled `<img src=x onerror=alert(1)>` (and a description holding a `<script>` tag and a URL) renders as escaped text: no `<img`, no `<script`, no link, no Edit or Delete.
- Playwright: Next then Previous leave `window.__noReload` true and `scrollY` unchanged, with `?month=` in the address; a day opens the panel; an entry is added and appears in that day's cell with no reload; Esc closes the panel and focus is on the day; clicking the chip opens the panel, Edit changes the title, Delete asks first and removes it. The flag is still true at the end.

## Not checked

- I did not look at the panel in a browser (light and dark, desktop and phone). The CSS uses only existing tokens, but the bottom sheet at 640px and the look of the compact form are unseen by me. The owner should look.
- Reading the page with a screen reader: day buttons carry the full date and the item count in their label, but I didn't try one.

## Rules checked

- Untrusted text (plan rule 1): imported titles, descriptions and source names are rendered by React as text; the panel gives imported items no link.
- Money (rule 3): amounts in summaries go through `formatMoney` from integer cents; a percentage milestone shows the percentage, not a computed amount.
- Logging (rule 9): no new logging.
- Service role (rule 8): not used; the panel calls the existing entries routes as the signed-in user.
- No new dependency.

## Found and fixed

Nothing failed in QA. Two things I got wrong while writing the tests, both mine: `formatMoney` puts a non-breaking space between the currency and the amount, and a `sed` replace ate the backslashes in a regex. Both fixed before the run above.
