# QA: C5 Lawyer pack

Solo mode, 9 Nov 2026. Branch `feat/C5-lawyer-pack`. It reads files from disk and gathers a project's whole record, so path safety and what must not leak are the focus.

## Checked

- `npm run check`: green (110 files, 2673 tests passed, 1 skipped).
- `npm run test:e2e`: 136 passed.
- Diff reviewed against `docs/PHASE2-PLAN.md` sections 2, 7.C5 and 11.
- **C-S6** (`tests/phase2/lawyer-pack.test.ts`, 10 tests, real migrations and RLS, real PDF merging; Chromium replaced by a renderer that makes tiny real PDFs, so each page's size says which source it came from):
  - Another user's project, and a malformed id, answer 404 and render nothing.
  - A stored path outside the archive is never read: a `../` path for both an invoice and the signed agreement, and, for an invoice, an absolute path, a drive letter, a backslash, a path that climbs out and comes back in, and a name that isn't a `.pdf`. The outside file's pages never appear in the pack, each is named on the cover, and the outside file is untouched.
  - **Done when:** the pack is one PDF in the order cover, signed agreement (2 pages), the newest invoice version, the timeline, then the demand letters; the contents table has the right page ranges; earlier invoice versions are named, not included.
  - It is kept in the archive as `<Client>/<Project>/Lawyer-pack-<date>.pdf` and returned as a PDF attachment; a second pack the same day is "(2)" and the first is never replaced.
  - A missing file, a file that isn't a PDF, an invoice with no saved PDF are named on the cover and the pack still builds; a pack that would pass 200 pages leaves the over-limit part out whole and says so, keeping the agreement.
  - The cover's statutory calculation matches a hand calculation (GBP 9.86 interest, GBP 70.00, total GBP 2,079.86) under an approved law, says plainly that none is calculated otherwise, and skips paid invoices.
  - The timeline has the email sent (subject and full text), the client's reply, and events, oldest first, with everything escaped (a `<script>` in a reply is shown as text); the cover and timeline contain no signing-token hash, no Gmail token ciphertext and nothing of another user (their client, freelancer, email address or thread).
- **Browser** (a throwaway Playwright spec, not committed; real Chromium): the Project page's "Lawyer pack" button downloads a real PDF (valid header, opens in `pdf-lib`, 2 pages here because the demo invoice had never been emailed, so no invoice PDF existed yet) and shows "Your lawyer pack is downloading"; no page errors.
